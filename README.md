# astrbot_plugin_music_request

群里点歌，免费听。

发「/点歌 周杰伦 晴天」，机器人搜索、挑出能播放的版本，以音乐卡片发出来（点击可在 QQ 内播放）。不需要 API Key，不需要会员账号。

## 1. 怎么用

```
/点歌 周杰伦 晴天
/来首歌 起风了
/听歌 稻香
/点歌                # 不带歌名，从默认列表里随机点一首
```

也可以 @ 机器人之后直接说「点歌 晴天」。

AI 开启时，说得随意一点也能识别：

```
/点歌 杰伦那首下雨天唱的
/点歌 来首适合加班听的
```

### 选第几首

点歌后默认会先列出候选，回复序号再播放：

```
「银河与星斗」找到 5 首，回复序号选择：
1. 银河与星斗 - yihuik苡慧  3:14
2. 银河与星斗 - 云鸢浅浅  3:08
3. 银河与星斗 - 苡慧  3:14
4. 银河与星斗 - 用户4938936155  2:54
5. 银河与星斗 (伴奏) - yihuik苡慧  3:14

120 秒内回复数字（1-5），或重新点歌
```

直接回 `2` 就播第二首。选中的那首如果因为版权播不了，会提示「换一个序号试试」，会话保留，不用重新点歌。

不想每次选的话，把 `enable_choice` 关掉，会直接播匹配度最高的一首。

## 2. AI 做了什么

只做两件事，都不碰音频本身：

1. **理解意图**：把「杰伦那首下雨天唱的」拆成 `{"artist":"周杰伦","title":"晴天"}`，再去搜索。拆不出来就退化成用原话搜索，不会卡住。
2. **搜不到时推荐**：如果关键词搜不到结果，让模型推荐一首真实存在的歌再搜一次。

模型不会编造歌曲信息，也不会参与选版本——选哪首、能不能播，全由插件按匹配度和实际探测结果决定。

## 3. 为什么有的歌放不了

插件同时接了四个音源，都能免 Key、免登录：

| 音源 | 搜索 | 取流 | 特点 |
|---|---|---|---|
| 网易云 `netease` | 公开接口 | 官方分享外链，302 到 CDN mp3 | 稳定，但版权歌会 404 |
| QQ 音乐 `qq` | 公开网关 | vkey 接口，部分歌能拿到 | 搜索覆盖更全（能搜到原版），但风控较严、部分歌未登录取不到流 |
| 酷我 `kuwo` | 公开接口 | `antiserver` 直接返回 mp3 直链 | 免费曲目、翻唱、伴奏覆盖好；版权原唱可能只有片段，探测不通过会自动跳过 |
| Audius `audius` | 开放 API | `/v1/tracks/{id}/stream` 302 到 mp3 | 独立音乐人、Lo-Fi、电子、翻唱；全免费无版权风险，中文歌少 |

四个源并发搜索、合并排序，点歌列表里会标 `[网易云]` / `[QQ音乐]` / `[酷我]` / `[Audius]`。播放时按来源分别探测，一个源不可播就换下一个，所以同一首歌可能同时出现两个平台的版本，选能播的那个就行。

QQ 音乐有个熔断：连续失败两次会暂停 10 分钟，避免每次点歌都白等一次请求。

不管用哪个源，都有共同限制：

- **VIP 独占、版权下架**的歌拿不到音频，这是平台侧的，不是插件能绕过的
- 插件会做三件事：搜索取多条 → 按歌名/歌手/时长排序（完整版优先、伴奏降权）→ 逐个探测，取第一个真能播的
- 播的是哪个版本，消息里会如实写清楚（比如「晴天 - 梦里啥都有」）

### 音源实测情况

写这个插件时挨个试过一圈公开接口，结论如下，避免你以为是插件的问题：

- **网易云**：可用，外链直接给 mp3
- **QQ 音乐**：搜索可用，取流只对部分歌有效；短时间频繁请求会返回 `code=2001`，等一会儿恢复
- **酷我**：可用（需带浏览器 UA + Referer，直接裸请求会返回「The request is illegal」）；免费曲目和翻唱基本都能取到流
- **咪咕**：接口重定向，无法直接调用
- **聚合 API（gdstudio）**：公开实例只开放了网易云和 Joox，没有带来额外覆盖
- **B 站**：能搜到大量原版，但音频流有 Referer 防盗链，QQ 客户端直接播放会 403
- **咪咕**：搜索接口返回 HTML（反爬），暂不可用
- **Audius**：可用，搜索和音频流都正常，台湾独立音乐/英文歌为主

想接自己的音源，实现 `music_source.py` 里的 `MusicSource` 三个方法（`search` / `probe` / `close`），在 `SOURCE_CLASSES` 里注册即可，上层不用改。

## 4. 配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enable` | 开 | 总开关 |
| `sources` | `["netease", "qq", "kuwo", "audius"]` | 音源列表，可只留 `netease`；多个音源并发搜索，结果会标来源 |
| `record_max_seconds` | 60 | 每段语音时长（秒） |
| `record_max_parts` | 6 | 最多发几段，超过只发前几段 |
| `use_ai` | 开 | 用 AI 理解点歌意图、搜不到时推荐 |
| `llm_provider_id` | 空 | AI 用的模型，留空跟随会话默认 |
| `default_keywords` | 5 首 | 只发「点歌」时随机挑一个 |
| `search_limit` | 10 | 搜索条数，多取几条排序更准 |
| `probe_limit` | 5 | 最多试几首能不能播，越大越慢但成功率越高 |
| `enable_choice` | 开 | 点歌后列出候选，回复序号选择；关掉直接播最好的那首 |
| `choice_count` | 5 | 候选数量（2-8） |
| `choice_timeout` | 120 | 选择等待时间，超时序号失效 |
| `send_mode` | `record` | `record` 发语音；`text` 只发歌名和直链 |
| `rate_limit_seconds` | 5 | 同一用户点歌冷却 |
| `request_timeout` | 10 | 接口超时 |

## 5. 发送方式

默认发**语音消息**（`record`）：把整首按每 60 秒切成多段，逐条发送，点开就能听完整首。
每段间隔 1 秒，避免触发平台频率限制；段数由 `record_max_parts` 控制（默认 6 段）。
消息里会标「（1/4）」这样的序号。

需要 ffmpeg，装在 PATH 里即可（`winget install Gyan.FFmpeg`）。没有 ffmpeg 时会退回直接发原始音频链接。

其他发送方式：`card` 音乐卡片（点击在 QQ 内播放）、`text` 只发歌名和直链。

### 为什么不默认发语音

AstrBot 的 `Record` 组件在发送前会把音频**统一转成 wav**（`convert_to_base64(target_format="wav")`）。一首 4 分钟的歌转完是几十 MB，napcat 处理不了，消息会直接消失，而且**不报错**——表现就是用户只收到一行「正在播放：xxx」，没有声音。

另外 AstrBot 自带的 `Music` 组件在当前版本有个 bug：`_type` 被当成 pydantic 私有属性，序列化后缺少 `type` 字段，napcat 收到会报「消息体无法解析」。napcat 又不支持 `type=163 + id` 的简写卡片，只能用 `custom` 并补齐所有字段。所以插件绕过了组件层，直接发标准 OneBot music 段。

`send_mode` 三个选项：

| 值 | 行为 |
|---|---|
| `card`（默认） | 音乐卡片，轻量，点击播放 |
| `text` | 只发歌名 + 音频直链 |
| `record` | 语音消息，整首歌基本发不出去，只适合点很短的音频 |

卡片发送失败（没有封面、协议端报错）会自动降级为文本 + 直链，不会静默失败。

## 6. 不响应时排查

1. 确认插件已加载：日志里应有 `[music] 已加载 | 启用=True | AI=True | 发送方式=record`
2. 命令是否被别的插件抢了？换 `@机器人 点歌 晴天` 试试
3. `点歌` 后面没有内容时会用默认关键词，如果默认列表为空会直接返回
4. 提示「没找到」：换个写法，带上歌手名，或者加「翻唱」两个字
5. 只收到一行歌名、没有卡片：说明卡片发送失败了，看日志里的 `[music] 音乐卡片发送失败`；可以先把 `send_mode` 改成 `text` 拿到直链
6. 改完配置要**重载插件**才生效
